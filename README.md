# Avito BC DS: Определение автоматизированного трафика по событиям

Решение тестового задания Avito Bootcamp DS. Для каждой `cookie_id` модель рассчитывает оценку принадлежности к трафику сервисов автоматизированного сбора данных. Результат записывается в `submission.csv` с колонками `cookie_id,score`.

Основная метрика задания - максимальная Precision среди порогов, при которых Recall не ниже 70%. ROC-AUC в ноутбуке служит дополнительной диагностикой.

## Запуск в Kaggle

1. Добавьте к ноутбуку приватный датасет с `train.csv`, `test.csv`, `events.csv` и `metric.py`.
2. Откройте `avito-bc-solution.ipynb`. В ячейке настроек путь должен соответствовать месту прикрепления датасета:

   ```python
   PATH = Path('/kaggle/input/datasets/callmejaso/avito-bc-ds')
   OUT = Path('/kaggle/working/antibot')
   ```

3. Если `optuna` или `catboost` отсутствуют в окружении, выполните в отдельной ячейке `%pip install catboost optuna` и перезапустите ядро.
4. Выполните **Restart Kernel and Run All**. Итоговый файл появится в `/kaggle/working/antibot/submission.csv`; скачайте именно его.

Путь к датасету в другом аккаунте Kaggle может отличаться. Перед запуском проверьте `PATH` командой `list(PATH.iterdir())`.

## Локальный запуск

Рекомендуется Python 3.12. Поместите `train.csv`, `test.csv`, `events.csv` и `metric.py` рядом с ноутбуком, как на снимке папки. Из этой папки выполните:

```bash
python -m venv .venv
```

Активируйте окружение (`.venv\Scripts\Activate.ps1` в Windows PowerShell или `source .venv/bin/activate` в Linux/macOS), затем:

```bash
python -m pip install -r requirements.txt
python -m jupyter notebook
```

В ячейке настроек ноутбука замените два пути:

```python
PATH = Path('.').resolve()
OUT = Path('output').resolve()
```

Откройте ноутбук через Jupyter и выполните **Restart Kernel and Run All**. Файл ответа появится в `output/submission.csv`. Ячейка с `sys.path.insert(0, str(PATH))` импортирует `metric.py` из этой же папки. Если данные лежат в отдельном каталоге, укажите его в `PATH`.

## Как устроено решение

Сначала события ограничиваются индивидуальным суточным окном `[window_start_ts, window_end_ts)` и удаляются полные дубликаты. Для каждой куки рассчитываются количества и доли действий, разнообразие просмотренных объявлений и запросов, паузы, возраст куки, характеристики клиента и агрегаты координат указателя. Сырые строки User-Agent и идентификаторы объявлений напрямую в модель не подаются.

Модели сравниваются на последовательных периодах: обучение на 6–13 апреля с проверкой на 14–16 апреля, затем обучение на 6–16 апреля с проверкой на 17–19 апреля. Периоды многократно использовались при разработке, поэтому полученные оценки являются внутренней валидацией. Для финального ответа CatBoost обучается на всём `train`. Четыре параметра модели выбраны в 15 попытках Optuna и должны быть зафиксированы в итоговой ячейке; повторять поиск для создания ответа не требуется.

На двух временных проверках CatBoost с признаками координат и подобранными параметрами получил P@R≥0.70 = 0.6432 и 0.7386 соответственно

## Проверка результата

Финальная ячейка проверяет состав и порядок `cookie_id`, две колонки файла, отсутствие повторов и пропусков, а также диапазон `score` от 0 до 1. Ожидается 4909 строк. После сохранения файл читается обратно и проверяется ещё раз

Зафиксированный `SEED = 42` позволяет повторить обучение в одинаковом окружении.
